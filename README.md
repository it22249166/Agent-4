## What makes v2 different

Agent 4 v2 **reads and understands the code** generated by Agent 2 before deciding
how to deploy it. It detects which architecture pattern was used, then generates
the most suitable deployment configuration automatically.

| Detected Architecture | Deployment Strategy |
|---|---|
| Microservices | Kubernetes manifests + docker-compose (dev) |
| Clean / Hexagonal | Multi-stage Dockerfile + prod compose |
| Event-Driven | docker-compose with broker services + workers |
| Layered MVC | docker-compose + Nginx + prod override |
| Monolithic | Single-container + Nginx |

## Architecture Detection

The analyzer scans:
- **Folder names** — `services/`, `controllers/`, `consumers/`, `domain/`
- **File names** — `use_case.py`, `repository.py`, `consumer.py`
- **Import statements** — `pika`, `sqlalchemy`, `httpx`, `celery`
- **Code patterns** — `APIRouter()`, `@abstractmethod`, `SERVICE_URL`

## Generated Files (by strategy)

| Strategy | Files Generated |
|---|---|
| Kubernetes | Dockerfile/service, docker-compose.yml, kubernetes/*.yaml, nginx.conf, .github/workflows/ci.yml |
| Multi-stage | Dockerfile (3-stage), docker-compose.yml, docker-compose.prod.yml, nginx.conf, CI/CD |
| Event-Driven | Dockerfile, docker-compose with broker + workers, CI/CD |
| Layered | Dockerfile, docker-compose, docker-compose.prod.yml, nginx.conf, CI/CD |
| Monolithic | Dockerfile, docker-compose, nginx.conf, CI/CD |

All strategies also include: `README.md`, `.env.example`, `setup.sh`, `architecture_report.json`

## Quick Start

**Windows:** double-click `start.bat`

**Mac/Linux:**
```bash
bash start.sh
```

**Manual:**
```bash
cd backend
python -m venv venv && source venv/bin/activate   # venv\Scripts\activate on Windows
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 0.0.0.0 --port 8004 --reload

# In a second terminal:
cd frontend && npm install && npm run dev
```

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Health check |
| POST | `/package` | Start packaging job |
| GET | `/status/{job_id}` | Poll — returns full architecture report when done |
| GET | `/download/{job_id}` | Download ZIP |
| POST | `/architecture/preview` | Analyse architecture without packaging |
| GET | `/jobs` | List all jobs |
